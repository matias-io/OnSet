### Recent regressions to preserve

- Grid-only rekordbox seeds no longer suppress historical-analysis import; missing historical key fields preserve metadata.
- Citation extraction includes incremental annotations, completed research items and final completed output; incomplete streams rejected. Original unconsulted citations stay in audit while claims become unverified. Batch validation and save are atomic.
- Multi-track context includes route seeds with carried outgoing rates and all referenced technique options; returned plans use original brief/revisions.
- **Actual outer BEGIN IMMEDIATE** protects per-track savepoints. Releasing an outermost SQLite SAVEPOINT previously committed before the final rekordbox-running check. Do not remove the outer transaction or weaken the fault-injection regression.
- Near-zero absolute signal with a supplied grid produces silence/absent events and no cues, rather than a fabricated bar-zero groove. Resolution version invalidates earlier conclusions while native feature cache remains reusable.
- Preview verifies actual source fingerprints before returning cached renders.
- Hot cues use rekordbox's pad numbering (`HOT_SLOT` D=5 … L=9; `is_hot_cue` covers Kind 1–9 except memory loops), and a hot rewrite also replaces OnSet's own cue of that name on another pad, so cues from the old numbering move instead of doubling. A manual cue on the new pad is preserved as a conflict. `apply()` records each track's prior ownership (`owned_before`) in the manifest, and `restore()` puts it back. Manifests written before this change lack it.
- `rekordbox-preview` with `{"repair_hot_slots": true}` previews a library-wide pad repair (`prepare_hot_slot_repair`). It moves OnSet's own hot cues that are still on the old numbering, changing only Kind. A cue whose new pad keeps another cue stays put and is listed. The apply takes a consistent backup, updates ownership and writes a restorable manifest. On a copy of the real library: 609 moves on 126 tracks, 12 cues left beside manual pads (Empty, Stardust, Push the feelings on), restore identical. In the app: track > Corrections > More tools > "Adopt cues from earlier versions in rekordbox" > "Find hot cues on the wrong pads" (60a0d84).

Manual, portable-export and before-restore backups are kept. Before this, 162 copies (14 GB) filled the disk twice on 2026-10-22; pruning the real workspace removed 140 and kept 21.

### Recording and replaying a set (visuals)

Tuning how scenes react no longer needs a live set each time. `onset.exe` can record the engine's `MusicState` every tick (120 Hz, about 400 bytes a tick, so a ten-minute set is around 30 MB) and the headless renderer replays it, so a scene or mapping change is compared on identical input. The format is `onset_core::recording` (little-endian, versioned, no file paths from the DJ's machine); the engine writes it through `EngineCommand::StartRecording`/`StopRecording`, and `onset_render::replay::Recording` reads it back (`frames()`, `at(time)`, `sampled(fps)`). Record while rekordbox plays (or with `--sim <title>`); the file closes when the window does:

```powershell
cargo run --release -p onset-visuals -- --record                       # recordings/set-<unix seconds>.onsetrec in the app's data folder (%LOCALAPPDATA%/Onset/Onset/data)
cargo run --release -p onset-visuals -- --record D:/sets/friday.onsetrec --exit-after 600
```

Replay it through one or more scenes, measuring each and optionally saving frames to diff against another build:

```powershell
$env:ONSET_RECORDING = 'D:/sets/friday.onsetrec'; $env:ONSET_REPLAY_SCENES = 'synthwave,crystal'; $env:ONSET_DUMP_DIR = 'D:/Offload/replay-before'
cargo test --release -p onset-render --test replay replay_recording -- --ignored --nocapture
```

`ONSET_REPLAY_FPS` (30), `ONSET_REPLAY_SIZE` (1920x1080), `ONSET_REPLAY_SECONDS` (all) and `ONSET_REPLAY_EVERY` (a PNG every 30 frames) narrow the run; without `ONSET_RECORDING` the checked-in synthetic fixture plays. That fixture, `crates/onset-render/tests/fixtures/synthetic.onsetrec` (four seconds of the gallery's build-up and drop at 30 Hz, no real music), is regenerated with `ONSET_UPDATE_FIXTURES=1 cargo test -p onset-render --test replay`; the same test checks it still matches the generator, and a second test replays it through a scene and asserts the drop shows. Recordings of real sets stay out of Git.
